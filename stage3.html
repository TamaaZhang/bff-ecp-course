    為什麼只換一層

    階段一的 BFF 分成好幾層，只有「資料來源轉接層」知道資料放在哪裡、要怎麼拿。換資料來源時，只要新增一個轉接層：

    檔案這個階段
    web/（前端）不動
    bff/src/graphql/（前端和 BFF 之間的約定）不動
    bff/src/meetingRooms/meetingRoomService.js（業務規則：檢查輸入、衝突、排序）不動
    bff/src/sources/sheetSource.js（Google Sheet 轉接層）不動，留著可以切回去
    bff/src/sources/ecpSource.js、ecpUnits.js新增：唯一會呼叫 ECP 的地方、ECP 白名單
    bff/src/config.js、index.js小改：讀 ECP 設定，依 DATA_SOURCE 選資料來源

    Sheet 和 ECP 哪裡不一樣

    這些差異全部關在 ecpSource.js 裡，其他程式看不到：

    Google SheetECP
    怎麼證明「我是誰」通行碼放在本文帳號密碼放在 Authorization 標頭（ECP 有自己的特殊格式）
    失敗時ok: falseHTTP 一樣是 200，回應裡有 _failed: true
    欄位名稱中文欄名（「主旨」）F 開頭（FName）；加 $ 是顯示文字（Taipei → 台北）
    編號R01、B001很長的亂碼（UUID），例如 1a2117f9-0390-…
    排序Apps Script 不排序ECP 也不能排序，回來的順序不固定

    排序、檢查輸入、衝突檢查本來就寫在 service，所以換成 ECP 一樣有效，不用重寫。

    A. 在 bff/.env 加上 ECP 設定

    1. 用記事本（Mac：文字編輯）打開 bff/.env，在最下面加上這四行：
      DATA_SOURCE=ecp ECP_BASE_URL=http://127.0.0.1:22821/aipower ECP_LOGIN_NAME=administrator ECP_LOGIN_PASSWORD='你的密碼'
    2. 把 你的密碼 換成你的 ECP 密碼（在 初始密碼.txt；如果你改過密碼，填新的），前後的單引號要留著。沒有單引號的話，密碼裡的 # 和後面的字會被當成註解切掉，ECP 就會說密碼錯。
    3. 存檔。Sheet 的兩行（SHEET_API_URL、SHEET_API_TOKEN）留著，驗收時會切回去比較。

    ECP 密碼是秘密：只寫在 bff/.env，不要貼到 AI 對話裡。AI 被設定成不能讀 .env，它也不需要看到密碼。

    密碼錯約 3 次，ECP 會把帳號鎖 30 分鐘，鎖住期間連 ECP 網頁也登不進去。BFF 收到一次帳密錯誤就會停止連線；看到 source_auth_failed 時，先檢查 bff/.env 的密碼再重新 npm start，不要一直重試。

    這一行可以告訴 AI 嗎
    DATA_SOURCE、ECP_BASE_URL、ECP_LOGIN_NAME可以（公開資訊）
    ECP_LOGIN_PASSWORD不可以

    起始包的 bff/.env.example 也有這幾行和說明，可以對照。

    請 AI 改接 ECP

    1. 先停掉 BFF（在跑 npm start 的終端機按 Ctrl+C）。
    2. 在 Claude Code 輸入：/bff-ecp
      Codex 使用者：把起始包 提示詞/3_改接ECP.md 的內容整份貼上。
    3. AI 會先問你四件事：階段一驗收過了嗎、階段二做完了嗎、單元編碼和欄位名稱和階段二的表格一樣嗎、bff/.env 加好 ECP 設定了嗎。都是就回答「是」。

      如果你在階段二用了不同的編碼或欄位名稱，這時告訴 AI 實際的名稱（這是公開資訊），它會寫進 ecpUnits.js。

    4. AI 開始寫程式。它每寫完一個檔案會說明那個檔案負責什麼。注意看它最後列出的檔案：前端、GraphQL、service 應該都沒有在裡面。
    5. 寫完後在 bff 資料夾執行 npm start，終端機應該印出「資料來源：ECP」。打開 http://localhost:4000。

    AI 如果要你把 ECP 密碼貼到對話裡，不要貼。密碼只放在 bff/.env。

    ECP 的資料不會每天變成「今天」。看板要查你在階段二建範例資料的那一天，才看得到「專案週會」「客戶簡報」。

    看懂程式

    可以直接問 AI 下面這些問題，請它指出是哪個檔案、哪一段：

    • ecpSource.js 的 Authorization 標頭是怎麼組出來的？為什麼密碼不會出現在 log？
    • ECP 回傳 _failed 的時候，BFF 怎麼決定要回 DATA-503、DATA-404 還是 DATA-502？
    • ecpUnits.js 的白名單擋了哪些東西？如果前端想查別的單元會怎樣？
    • 為什麼排序和衝突檢查不用為 ECP 重寫？

    一個值得記住的發現

    在 ECP 畫面上，「會議室」是必填，不選就存不了。但透過 API 寫入時，ECP 不檢查必填，也不檢查選的會議室存不存在：畫面上的檢查只在畫面。

    所以 BFF 的 service 在寫入前檢查主旨、會議室、時間，不是多此一舉，而是真正的防線。
